# Руководство для агентов

## Назначение проекта

Это персональное портфолио и блог на Next.js. Главная страница собирается из данных резюме, а статьи блога — из MDX-файлов. При изменениях сохраняйте текущую модель: контент отделён от компонентов, серверные компоненты используются по умолчанию, клиентские границы добавляются только для интерактивности.

## Стек

- Node.js 18+, пакетный менеджер `pnpm`.
- Next.js 16 с App Router, React 19 и TypeScript в строгом режиме.
- Tailwind CSS 4 через PostCSS; дизайн-токены находятся в `src/app/globals.css`.
- Radix UI и shadcn/ui для базовых компонентов, Lucide для иконок.
- Motion/Magic UI для анимаций и декоративных эффектов.
- Content Collections + MDX для блога, Remark GFM и Rehype Pretty Code для разметки и подсветки.

## Быстрые команды

```bash
pnpm install
pnpm dev
pnpm lint
pnpm build
pnpm start
```

Перед завершением изменения запускайте как минимум `pnpm lint`. Для правок маршрутов, конфигурации, MDX-схемы или зависимостей также запускайте `pnpm build`.

## Карта репозитория

- `src/app/` — маршруты App Router, общая раскладка, metadata, Open Graph и глобальные стили.
- `src/app/page.tsx` — композиция главной страницы.
- `src/app/blog/` — список статей, пагинация, страницы статей и их metadata.
- `src/data/resume.tsx` — единый источник данных портфолио: профиль, опыт, образование, навыки, проекты, контакты и хакатоны.
- `src/components/section/` — крупные секции главной страницы.
- `src/components/ui/` — низкоуровневые переиспользуемые компоненты.
- `src/components/magicui/` — анимированные и декоративные компоненты.
- `src/components/mdx/` и `src/mdx-components.tsx` — отображение MDX, блоков кода и медиа.
- `src/lib/` — чистые утилиты пагинации, классов, дат и Remark-плагин.
- `content/` — статьи `.mdx`.
- `public/` — локальные изображения, логотипы и шрифты.
- `content-collections.ts` — схема и компиляция коллекции статей.

## Правила внесения изменений

### Контент портфолио

- Обновляйте персональные данные в `src/data/resume.tsx`, а не дублируйте их в компонентах.
- Для локальных изображений помещайте файл в `public/` и используйте путь вида `/image.png`.
- Сохраняйте форму элементов существующих массивов: она выводится напрямую через `.map()` и закреплена `as const`.
- Внешние ссылки должны открываться с `target="_blank"` и `rel="noopener noreferrer"`.

### Блог

- Добавляйте статью как `content/<slug>.mdx`.
- Обязательный frontmatter: `title`, `publishedAt`, `summary`. Поддерживаются `updatedAt`, `author` и `image`.
- Slug формируется из относительного пути файла без `.mdx`; переименование файла меняет URL.
- Для новых MDX-компонентов сначала зарегистрируйте компонент в `src/mdx-components.tsx`.
- Если меняется frontmatter, синхронно обновляйте Zod-схему в `content-collections.ts` и места чтения поля.
- Не импортируйте `.content-collections/generated` напрямую: используйте алиас `content-collections`.

### React и Next.js

- Оставляйте компоненты серверными по умолчанию. Добавляйте `"use client"` только при использовании состояния, эффектов, обработчиков или браузерных API.
- Не переносите загрузку `allPosts` в клиент: коллекция предназначена для build/server-слоя.
- Для динамических страниц блога сохраняйте `generateStaticParams`, `generateMetadata` и обработку `notFound()`.
- Metadata сайта должна продолжать использовать `DATA`, чтобы имя, URL и описание не расходились между страницами.
- Импорты внутри `src` оформляйте через алиас `@/`.

### UI и стили

- Используйте существующие токены (`background`, `foreground`, `muted`, `border`, `primary` и другие), а не жёстко заданные цвета, если цвет не несёт специального смысла.
- Поддерживайте светлую и тёмную темы; проверяйте классы `dark:` и контраст в обеих.
- Сохраняйте текущую компактную ширину контента (`max-w-2xl`) и mobile-first адаптивность.
- Перед созданием нового примитива проверьте `src/components/ui/`; для объединения классов используйте `cn()` из `src/lib/utils.ts`.
- Учитывайте доступность: видимый focus state, `aria-label` для иконок-ссылок, осмысленный `alt`, управление с клавиатуры.
- Анимации должны оставаться декоративными и не мешать чтению или навигации.

## Проверка результата

1. Запустите `pnpm lint`.
2. Для структурных изменений запустите `pnpm build`; это также проверит генерацию Content Collections и статических blog-slug.
3. В `pnpm dev` проверьте `/`, `/blog`, существующую `/blog/<slug>` и несуществующий slug.
4. Проверьте мобильную ширину, светлую/тёмную темы, клавиатурный focus и внешние ссылки.
5. Не коммитьте `.next/`, сгенерированные каталоги, логи и локальные секреты.

## Ограничения и осторожность

- В проекте нет тестового раннера; не заявляйте о покрытии тестами без его добавления.
- README частично описывает более старые версии стека. Источником истины для версий являются `package.json` и lock-файл.
- Не заменяйте пользовательские данные или дизайн шаблонными значениями без явного запроса.
- Не выполняйте массовую переработку UI при локальной задаче: секции связаны общей типографикой, токенами и ритмом.
