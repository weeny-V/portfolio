# Дизайн и архитектура проекта

## Обзор

Проект — одностраничное персональное портфолио с отдельным статически генерируемым блогом. Архитектура намеренно проста: структурированные данные портфолио и MDX-контент подаются в серверные React-компоненты, а небольшие клиентские островки обеспечивают тему, accordion, анимации и обработку ошибок изображений.

Основные цели дизайна:

- менять содержание портфолио в одном файле без переписывания представления;
- генерировать SEO-дружественные страницы статей на этапе сборки;
- сохранять минималистичную, адаптивную и тематизируемую визуальную систему;
- не отправлять клиенту JavaScript там, где достаточно серверного HTML.

## Поток данных

```text
src/data/resume.tsx
        |
        +--> layout metadata / navbar / главная страница / секции

content/*.mdx
        |
        v
content-collections.ts
  Zod validation -> Remark GFM + code metadata -> compiled MDX
        |
        v
generated allPosts
        |
        +--> /blog (сортировка и пагинация)
        +--> /blog/[slug] (статическая страница, metadata, JSON-LD)
```

`DATA` — источник истины для портфолио и глобальной идентичности сайта. `allPosts` — build-time источник истины для блога. Компоненты представления не хранят отдельную копию этих данных.

## Маршруты и рендеринг

### Общая раскладка

`src/app/layout.tsx` подключает Geist/Geist Mono, глобальные стили, провайдер темы и tooltip, декоративную сетку, ограничитель ширины и фиксированную нижнюю навигацию. Глобальная metadata строится из `DATA`.

`ThemeProvider` — клиентская граница над `next-themes`; остальная раскладка остаётся серверной. Фоновая сетка и navbar общие для всех страниц.

### `/`

`src/app/page.tsx` компонует hero, about, work, education, skills, projects, hackathons и contact. Большинство секций — серверные и получают данные импортом `DATA`. Клиентскими являются только элементы, которым нужна интерактивность, например accordion опыта и карточки с реакцией на ошибку загрузки изображения.

### `/blog`

Страница получает `allPosts`, сортирует записи по `publishedAt` по убыванию и применяет серверную пагинацию по query-параметру `page`. Размер страницы — пять записей. `normalizePage` ограничивает значение доступным диапазоном, а `paginate` возвращает элементы и metadata пагинации.

### `/blog/[slug]`

Slug выводится из пути MDX-файла. `generateStaticParams` перечисляет статьи для статической генерации; `generateMetadata` строит Open Graph/Twitter metadata; неизвестный slug вызывает `notFound()`. Страница также добавляет JSON-LD типа `BlogPosting`, форматирует дату и показывает переходы к соседним статьям.

## Контентный конвейер

Коллекция `posts` определена в `content-collections.ts`. Zod проверяет frontmatter и гарантирует наличие заголовка, даты публикации, краткого описания и содержимого. Во время transform MDX компилируется с:

- `remark-gfm` для таблиц, task lists и другой GitHub-flavored разметки;
- `remarkCodeMeta` для переноса metadata code fence в `data-meta` и `data-title`;
- настроенным отображением через `src/mdx-components.tsx`.

MDX renderer заменяет стандартные `pre`, `code`, `hr` и `table`, а также предоставляет `MediaContainer`. В результате оформление статьи централизовано и не зависит от ручной HTML-разметки в каждом посте.

## Компонентные слои

### Секции

`src/components/section/` содержит крупные смысловые блоки главной страницы. Они отвечают за композицию и преобразуют массивы `DATA` в карточки, timeline и ссылки.

### Доменные компоненты

`ProjectCard`, `Timeline`, `Navbar` и MDX-компоненты выражают повторяемые паттерны приложения. Они могут собирать несколько UI-примитивов и содержать ограниченную интерактивность.

### UI-примитивы

`src/components/ui/` — слой Radix/shadcn-подобных компонентов: button, badge, card, accordion, avatar, separator и tooltip. Эти компоненты должны оставаться универсальными и не импортировать данные резюме.

### Декоративные компоненты

`src/components/magicui/` отвечает за Blur Fade, Dock и Flickering Grid. Декоративное поведение отделено от контента, поэтому его можно менять без изменения модели данных.

## Визуальная система

В `src/app/globals.css` Tailwind CSS 4 подключён через `@import`, а семантические CSS-переменные объявлены для светлой и тёмной тем. Цвета компонентов должны ссылаться на роли (`background`, `card`, `muted`, `border`, `primary`), а не на конкретную палитру.

Характер дизайна:

- узкая колонка контента до `max-w-2xl`;
- нейтральная монохромная палитра;
- компактные скруглённые поверхности с тонкими границами;
- Geist для текста и Geist Mono для технических деталей;
- постепенное появление секций через Blur Fade;
- фиксированный Dock снизу как основная навигация;
- responsive layout с mobile-first классами;
- одинаковая семантика токенов в светлой и тёмной темах.

Отдельный блок `.prose` задаёт типографику статей, подсветку Shiki в обеих темах, таблицы, цитаты, task lists и inline code.

## SEO, безопасность и доступность

SEO реализовано на трёх уровнях: глобальная metadata, metadata списка блога и metadata/JSON-LD каждой статьи. Open Graph-изображения имеют отдельные route-файлы.

`next.config.mjs` добавляет для всех маршрутов заголовки `nosniff`, запрет iframe, строгую referrer policy и отключение камеры, микрофона и геолокации. JSON-LD экранирует символ `<` перед вставкой.

Интерактивные элементы используют focus ring и aria-label там, где одного визуального значка недостаточно. Radix обеспечивает базовую семантику сложных примитивов. При дальнейшем развитии следует сохранять клавиатурную навигацию, контраст тем и осмысленные alt-тексты.

## Точки расширения

- Новое поле портфолио: добавить в `DATA`, затем отобразить в подходящей секции.
- Новая секция главной: создать компонент в `src/components/section/` и подключить в `src/app/page.tsx`.
- Новая статья: добавить MDX-файл с валидным frontmatter в `content/`.
- Новый тип MDX-разметки: реализовать компонент и зарегистрировать его в `src/mdx-components.tsx`.
- Новое поле статьи: расширить Zod-схему и потребителей metadata/rendering.
- Новый UI-примитив: разместить в `src/components/ui/`, сохранив семантические токены и API, независимый от `DATA`.

## Известные компромиссы

- Данные резюме находятся в TSX, поскольку содержат ссылки на React-компоненты иконок; это удобно для типизации, но связывает контент с кодом.
- Сортировка статей повторяется на страницах списка и отдельной статьи; при усложнении блога её стоит вынести в общую утилиту.
- Пагинация основана на query-параметре и выполняется поверх уже загруженной build-time коллекции, что подходит для небольшого статического блога.
- Часть изображений загружается с внешних URL через обычный `<img>`, поэтому оптимизация Next Image применяется не везде.
- Автоматических тестов нет; основная защита от регрессий сейчас — строгий TypeScript, ESLint, build-time валидация контента и ручная визуальная проверка.
